## ISSUE-013 — Cookie 认证缺少 CSRF 防护

**Fix:** Double-submit CSRF cookie（`openclaw_csrf`）+ `CsrfMiddleware`；纯 Cookie 写操作（无 Bearer/API Key）须带 `X-CSRF-Token`。登录/注册/刷新/session 签发 CSRF cookie；前端 `getAuthHeaders` 自动附带。

---

## ISSUE-014 — Legacy Portal Session 仍保留

**Fix:** 生产模式禁用 `openclaw_portal_session` 校验；禁用 legacy API Key 映射 ADMIN；`POST /public/auth/session` 在生产返回 403。

---

## ISSUE-015 — 开放注册与首用户 ADMIN 默认开启

**Fix:** 生产 `startup_checks` 强制 `OPENCLAW_ALLOW_REGISTRATION=false` 与 `OPENCLAW_FIRST_USER_IS_ADMIN=false`。

---

## ISSUE-016 — 演示账号默认凭据

**Fix:** 新增 `OPENCLAW_DEMO_SEED_ENABLED`（默认 true）；生产要求 `false`；`run_multi_user_migrations` 仅在启用时 seed demo。

---

## ISSUE-017 — Docker Compose 弱数据库密码

**Fix:** Compose 移除 DSN/Postgres 弱默认值，改为 `${VAR:?}` 强制 `.env` 配置；生产 startup 拒绝 DSN 含 `openclaw_dev` / `replace_me`。

---

## ISSUE-018 — retry_ingest 缺少所有权校验

**Fix:** 抽取 `_assert_ingest_owner()`，`retry_ingest` 与 `get_ingest_status` 共用，防止未来实现 IDOR。

---

## ISSUE-019 — ADMIN 绕过 owner_clause（架构性）

**Fix:** 在 `QueryContext` 文档中说明 ADMIN 全量访问为单租户运维模型；scoped API Key / 组织租户为后续产品扩展。**未改变运行时行为。**

---

## Manual Testing

1. Cookie 写操作无 CSRF → 403；带 `X-CSRF-Token` → 正常。
2. 生产模式：portal session / legacy session / legacy API Key 不可用。
