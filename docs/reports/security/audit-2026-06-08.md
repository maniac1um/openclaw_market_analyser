## 发现问题

---

### ISSUE-001

**Risk Level**：**High**

**Issue**：OpenClaw Monitoring API 多个端点缺少 `monitor_id` 租户归属校验（IDOR）

**Impact**：持有任意有效 API Key 的用户，若知道（或枚举）其他用户的 `monitor_id`，可读取其价格摘要、向其监测任务追加 URL、触发 `run-once` 写入观测数据（当 `OPENCLAW_MONITORING_ALLOW_SERVER_SCRAPE=true` 时还可触发服务端 HTTP 抓取）。Public 门户读路径已有 `monitor_accessible()`，但 OpenClaw Agent 路径未复用。

**Affected Files**：
- `app/api/v1/openclaw.py`（`run_monitoring_once`、`get_monitoring_summary`、`add_monitoring_urls`）
- `app/services/monitoring_service.py`（`get_summary`、`add_urls`、`run_once` — 仅校验 monitor 存在，不校验 `user_id`）

**Proof**：

```182:200:app/api/v1/openclaw.py
def run_monitoring_once(
    monitor_id: str,
    _: None = Depends(verify_user_api_key),
) -> MonitoringRunOnceResponse:
    ...
    try:
        result = service.run_once(monitor_id=monitor_id)
```

```248:268:app/api/v1/openclaw.py
def get_monitoring_summary(
    monitor_id: str,
    window_days: int = 7,
    _: None = Depends(verify_user_api_key),
) -> MonitoringSummaryResponse:
    ...
    result = service.get_summary(monitor_id=monitor_id, window_days=window_days)
```

对比 Public API 的正确模式：

```116:121:app/api/v1/public.py
def public_monitoring_timeseries(monitor_id: str, ctx: QueryCtx, window_days: int = 30) -> dict:
    ...
    if not pq.monitor_accessible(monitor_id, ctx):
        raise HTTPException(status_code=404, detail="Monitor not found")
```

已有测试仅覆盖 `observations/ingest` 的越权（`test_user_cannot_ingest_to_other_monitor`），**未覆盖** `summary` / `run-once` / `urls`。

**Fix Recommendation**：
1. 在 `MonitoringService` 增加 `assert_monitor_owner(monitor_id, user_id, role)` 或在各方法入口调用 `monitor_accessible(monitor_id, QueryContext(...))`。
2. OpenClaw 路由层传入 `user: User = Depends(verify_user_api_key)` 并校验归属；ADMIN 可豁免。
3. 补充 IDOR 集成测试：`user_b` 调用 `user_a` 的 `monitor_id` → 404。

### ISSUE-002

**Risk Level**：**High**

**Issue**：OpenClaw `GET /openclaw/news/library` 返回全租户新闻库数据

**Impact**：任意认证用户（API Key）可读取所有用户写入 `news_library` 的条目，包括标题、摘要、来源 URL，构成跨租户信息泄露。

**Affected Files**：
- `app/api/v1/openclaw.py`（`list_news_library_items`）

**Proof**：

```375:416:app/api/v1/openclaw.py
def list_news_library_items(
    keyword: str | None = None,
    limit: int = 100,
    _: None = Depends(verify_user_api_key),

    ...
    base_sql = """
    SELECT id, keyword, summary, source_url, title, source_name, published_at, created_at
    FROM news_library

    # 无 WHERE user_id = ...
```

Public 侧 `list_news_library_from_db` 已使用 `ctx.owner_clause()`，OpenClaw 侧不一致。

2. 补充跨用户列表隔离测试。

### ISSUE-006

**Risk Level**：**Medium**

**Issue**：Refresh Token Cookie 缺少 `Secure` 标志

**Impact**：在 HTTPS 生产环境中，若存在混合内容或中间人降级攻击面，Refresh Cookie 可能经明文 HTTP 传输，导致会话劫持。

**Affected Files**：
- `app/api/v1/auth.py`（`_set_refresh_cookie`）

**Proof**：

```29:37:app/api/v1/auth.py

    response.set_cookie(
        key=REFRESH_COOKIE,
        value=refresh_token,
        httponly=True,
        samesite="lax",
        max_age=settings.jwt_refresh_ttl_seconds,
        path="/",
    )
    # 无 secure=settings.cookie_secure 或基于 production_mode 的设置
```

**Fix Recommendation**：
1. 增加 `OPENCLAW_COOKIE_SECURE`（生产默认 `true`），设置 `secure=True`。
2. 可选：增加 `OPENCLAW_COOKIE_DOMAIN` 显式配置。

### ISSUE-007

**Risk Level**：**Medium**

**Issue**：`OPENCLAW_PRODUCTION=true` 未校验 JWT Secret 强度

**Impact**：生产环境若仍使用默认 `dev-jwt-secret-change-me-in-production`，攻击者可伪造任意用户 JWT，完全绕过认证。

**Affected Files**：
- `app/core/startup_checks.py`
- `app/core/config.py`（`jwt_secret` 默认值）

**Proof**：`validate_security_config()` 校验 API Key、HMAC、签名、OpenAPI 等，**未包含** `jwt_secret` 弱值检测。默认：

```70:70:app/core/config.py

```

**Fix Recommendation**：在 `production_mode` 下拒绝长度 < 32 或命中弱值列表的 `jwt_secret`（与 API Key 校验对称）。

### ISSUE-008

**Risk Level**：**Medium**

**Issue**：Rate Limit 与登录锁定使用进程内内存，多 Worker / 多实例无效

**Impact**：Uvicorn 多 worker 或水平扩展部署时，攻击者可对单 worker 分散请求绕过全局限速；登录暴力破解防护同样可被稀释。

**Affected Files**：
- `app/middleware/security.py`（`RateLimitMiddleware._hits`）
- `app/core/auth_service.py`（`_login_attempts`）
- `app/api/v1/chat.py`（`_user_message_times`）

**Proof**：

```85:87:app/middleware/security.py
    def __init__(self, app) -> None:
        super().__init__(app)
```

### ISSUE-009

**Risk Level**：**Medium**

**Issue**：WebSocket 支持通过 Query 参数 `?token=` 传递 JWT

**Impact**：JWT 可能出现在访问日志、Referer、浏览器历史或代理日志中，扩大 Token 泄露面。

**Affected Files**：
- `app/api/v1/chat.py`（`chat_ws`：`bearer = websocket.query_params.get("token")`）


2. 或文档明确禁止并在 `production_mode` 下拒绝 query token。

### ISSUE-010

**Risk Level**：**Medium**

**Issue**：API Key 与 Refresh Token 使用裸 SHA-256 存储

**Impact**：若 `user_api_keys` / `user_sessions` 表泄露，SHA-256 无 salt/work factor，对高熵随机 Key 风险较低，但仍弱于 Argon2/bcrypt；且与密码哈希（Argon2）策略不一致。

**Affected Files**：
- `app/db/user_queries.py`（`hash_api_key`）

**Proof**：

```282:283:app/db/user_queries.py
def hash_api_key(raw_key: str) -> str:
    return hashlib.sha256(raw_key.encode("utf-8")).hexdigest()
```

**Fix Recommendation**：改用 Argon2id 或 HMAC-SHA256(server_pepper, key)；迁移时双读旧 hash。

### ISSUE-013

**Risk Level**：**Low**

**Issue**：Cookie 认证下缺少 CSRF Token，依赖 SameSite=Lax

**Impact**：对跨站 POST 有一定防护，但顶级导航 + GET 预检等场景下，攻击者仍可能诱导已登录用户触发部分写操作（如 bulk-delete）。风险低于经典 Session CSRF，但在多子域部署时需评估。

**Affected Files**：
- `app/api/v1/auth.py`（Refresh Cookie `samesite="lax"`）
- 所有 `credentials: 'include'` 的 Public 写端点

**Fix Recommendation**：
1. 敏感写操作要求 `Authorization: Bearer` 或自定义 `X-CSRF-Token`。
2. 或将 Refresh Cookie 改为 `SameSite=Strict`（评估 OAuth/第三方回调影响）。
