# OpenClaw 新用户首次体验优化方案

**角色**：Product Experience Agent  
**日期**：2026-06-08  
**范围**：Landing Page · Quick Start · Onboarding（Welcome Guide）  
**约束**：本文档为设计方案，不涉及代码实现。

---

## 1. 执行摘要

OpenClaw 分析平台当前是一个**全登录门禁**的产品门户：未登录用户访问任意路径都会被重定向到登录页，首页为 AI 对话界面。新用户无法在未注册前理解产品价值，注册后也缺少引导，容易在空状态页面（无报告、无监测任务）中迷失。

本方案提出三层体验结构：

| 层级 | 目标用户 | 核心目标 |
|------|----------|----------|
| **Landing Page** | 未登录访客 | 30 秒内理解「这是什么、能做什么、长什么样」 |
| **Quick Start** | 刚注册 / 首次登录 | 5 分钟内完成第一个关键词监测闭环 |
| **Onboarding（Welcome Guide）** | 首次登录用户 | 按步骤引导完成 4 项关键操作 |

**预期效果**：降低注册前流失、缩短 Time-to-First-Value（TTFV）、减少功能页空状态困惑。

## 2. 现状分析

### 2.1 路由与访问控制

```
访客 → 任意 URL
  ├─ /login, /register     → 纯表单页（无品牌叙事）
  └─ 其他路径              → ProtectedRoute → 重定向 /login
```

- `ProtectedRoute` 虽保存 `state.from`（原访问路径），但登录/注册成功后**固定跳转 `/`**，深度链接意图丢失。
- 公开路由仅 `/login`、`/register`，**无营销/预览页**。

### 2.2 首页（`/` → ChatPage）

| 维度 | 现状 | 问题 |
|------|------|------|
| 定位 | AI 对话工作台 | 对新用户是「空白聊天框」，不知从何问起 |
| 空状态文案 | 「有什么可以帮你？」+ 一句功能描述 | 信息量少，无示例、无 CTA 链路 |
| 前置条件 | 需 Gateway 连接 | 未配置 Gateway 时体验断裂，Landing 无法提前说明 |
| 价值展示 | 无 | 访客看不到对话能力以外的核心产出（报告、图表） |

### 2.3 登录页（`/login`）

- 居中 Card：标题「登录」+ 副标题「OpenClaw 分析平台」
- 字段：邮箱、密码
- 链接：跳转注册
- **缺失**：产品价值说明、功能预览、返回 Landing 的入口、Social proof

### 2.4 注册页（`/register`）

- 居中 Card：标题「注册」+ 副标题「创建您的 OpenClaw 账号」
- 字段：邮箱、用户名、密码（含格式提示）
- **缺失**：注册动机强化、Quick Start 预期、隐私/数据隔离说明

### 2.5 登录后首次体验

| 页面 | 空状态文案 | 用户困惑点 |
|------|------------|------------|
| `/reports` | 「让 OpenClaw 提交分析报告后将在此展示」 | 不知道如何触发第一份报告 |
| `/price-trend` | 「前往工作流创建监测任务」 | 与工作流关系不清晰 |
| `/workflow` | 功能密集，无引导 | 不知先创建监测还是先跑分析 |
| `/account` | API Key 说明面向 Agent 集成 | 个人用户 vs 开发者路径未区分 |

**结论**：产品能力完整，但**价值传达链断裂**——访客看不到成果样例，新用户看不到操作顺序。

## 3. 目标用户与场景

### 3.1 Persona A — 市场分析员（Primary）

- **目标**：跟踪某品类/关键词的市场情绪与价格变化
- **技术背景**：低，使用 Web 界面为主
- **成功标准**：看到第一份专题分析报告 + 价格趋势图

### 3.2 Persona B — 集成开发者（Secondary）

- **目标**：通过 OpenClaw Agent / Cursor Skill 自动提交报告
- **技术背景**：高，需要 API Key 与文档
- **成功标准**：生成 API Key，完成一次 Agent 入站

### 3.3 关键用户故事

1. **作为访客**，我希望在不注册的情况下看到示例报告和价格图表，以便判断产品是否适合我。
2. **作为新注册用户**，我希望被引导完成「关键词 → 监测 → 报告」最小闭环，而不是面对空白 Dashboard。
3. **作为开发者**，我希望在 Onboarding 中快速找到 API Key 与文档入口，而不必在账户页自行摸索。

## 4. 信息架构与路由设计

### 4.1 建议路由结构

```
/                          → Landing Page（公开）
/login                     → 登录（公开，保留 Landing 导航）
/register                  → 注册（公开）
/app                       → 应用入口（Protected，原 / 聊天首页）
/app/reports               → 专题分析（Protected）
/app/news                  → 新闻动态
/app/price-trend           → 价格趋势
/app/keyword-tracking      → 关键词追踪
/app/workflow              → 工作流
/app/account               → 账户 / API Key
/demo/report/:slug         → 示例报告详情（公开，虚构静态数据）
/demo/price-trend          → 价格趋势示例（公开，虚构静态数据）
```

> **已确认**：`/` **永久公开**为 Landing Page；聊天首页固定迁至 `/app`。老书签 `/` 在已登录态可 302 至 `/app`（可选）；未登录访问 `/app/*` 仍走 ProtectedRoute。

### 4.2 登录后跳转逻辑

```
注册/登录成功
  ├─ 若 state.from 存在且为 /app/* → 跳转 state.from
  ├─ 若为 demo 试用账号 → /app（聊天首页，跳过 Welcome Guide，见 §5.8）
  ├─ 若用户 onboarding_completed = false → /app?welcome=1（弹出 Welcome Guide）
  └─ 否则 → /app（聊天首页，已确认默认页）
```

**已确认**：首次登录/注册成功后**默认进入聊天页 `/app`**，不在工作流页落地。

## 6. Quick Start 设计

Quick Start 是 Landing Page 上的**概览**，也是登录后 Welcome Guide 的**文字版索引**。

### 6.1 四步流程（与 Onboarding 一致）

```
Step 1 创建关键词          Step 2 获取 API Key
      ↓                        ↓
  工作流 · 创建监测        账户 · 生成 Key（Agent 集成可选）
      ↓                        ↓
Step 3 创建定时任务        Step 4 查看分析报告
      ↓                        ↓
  工作流 · 联合分析/调度    专题分析 · 报告列表
```

### 6.2 两条路径分流

| 路径 | 适用用户 | 步骤侧重 |
|------|----------|----------|
| **门户路径**（默认） | Persona A | Step 1 → Step 3 → Step 4（Step 2 **默认折叠**） |
| **开发者路径** | Persona B | 展开 Step 2，附 `/docs` 与 Skill 说明 |

Landing 上默认展示门户路径（三步主流程）；开发者路径通过「我是开发者，用 API 集成」展开 Step 2。

**Step 2 折叠决策（已确认）**：对纯 Web 用户，Step 2 **默认折叠**为「高级 · 可选 · Agent 集成」。理由：主 Persona 为市场分析员，API Key 仅开发者需要；折叠可减少 Welcome Guide 认知负担，进度条按 **3 步主流程 + 1 可选附加** 展示。

### 6.3 预估耗时

| 步骤 | 操作 | 预估时间 |
|------|------|----------|
| 注册 | 填写表单 | 1 min |
| Step 1 | 工作流输入关键词并创建监测 | 2 min |
| Step 3 | 触发一次联合分析 | 1 min（等待异步可后台进行） |
| Step 4 | 打开报告页查看 | 1 min |

**Quick Start 承诺**：「10 分钟内看到第一份分析产出」（含 Agent/Gateway 就绪前提说明）。

## 7. Onboarding — Welcome Guide 设计

### 7.1 触发条件

| 条件 | 行为 |
|------|------|
| 首次登录/注册成功 | 自动弹出 Welcome Guide（Modal 或全屏 Sheet） |
| `localStorage.oc_onboarding_done = '1'` | 不再自动弹出 |
| 用户菜单「新手引导」 | 可手动重新打开 |
| 完成全部 4 步或点击「跳过」 | 写入完成标记 |

> 实现时可同步服务端 `users.onboarding_completed` 字段（可选，便于跨设备）。

### 7.2 Welcome Guide 结构

```
┌──────────────────────────────────────────────────┐
│  欢迎使用 OpenClaw，{username}！                    │
│  按以下 3 步快速上手，约需 10 分钟                   │
│  ─────────────────────────────────────────────   │
│  ● Step 1  创建关键词          [未完成] [去完成 →]  │
│  ○ Step 3  创建定时任务        [未完成] [去完成 →]  │
│  ○ Step 4  查看分析报告        [未完成] [去完成 →]  │
│  ─────────────────────────────────────────────   │
│  ▸ 高级 · 可选  Step 2  获取 API Key  [展开 →]     │
│  ─────────────────────────────────────────────   │
│  进度: ██░░ 1/3          [跳过引导]  [稍后提醒]    │
└──────────────────────────────────────────────────┘
```

主进度 **3 步**（1 → 3 → 4）；Step 2 折叠在「高级 · 可选」区，不计入主进度分母。

### 7.3 各步骤详细设计

#### Step 1 — 创建关键词

| 项 | 内容 |
|----|------|
| 目标 | 在工作流中创建第一个价格监测任务 |
| 引导方式 | 点击「去完成」→ 导航 `/app/workflow`，高亮「创建监测」输入框（Spotlight/Coach mark） |
| 完成判定 | 调用 `api.workOverview()` 返回 `monitor_count >= 1`，或本地事件 `onboarding:monitor_created` |
| 文案 | 「输入您要追踪的市场关键词，例如：锂电池、螺纹钢。系统将据此采集价格与相关新闻。」 |
| 失败兜底 | Gateway 未连接时显示警告 + 链接部署文档，仍允许标记「已完成」避免阻塞 |

#### Step 2 — 获取 API Key（高级 · 可选，默认折叠）

| 项 | 内容 |
|----|------|
| 展示 | 默认折叠；点击「高级 · 可选」或「我是开发者」展开 |
| 目标 | 了解并（可选）创建 API Key，供 OpenClaw Agent 使用 |
| 引导方式 | 导航 `/app/account`，高亮 API Key 创建区 |
| 完成判定 | 创建过 Key **或** 用户点击「暂不需要」；**不计入主进度 3/3** |
| 文案 | 「若您通过 OpenClaw Agent / Cursor Skill 自动提交报告，请在此生成 Key 并配置 `X-Api-Key`。」 |
| 附链 | `/docs`、Account 页已有集成说明 |

#### Step 3 — 创建定时任务

| 项 | 内容 |
|----|------|
| 目标 | 触发联合分析或了解外部调度配置 |
| 引导方式 | 返回 `/app/workflow`，高亮「触发联合分析」或「调度运行记录」区 |
| 完成判定 | 成功调用 `POST /workflow/analysis/run` **或** 存在 scheduler run 记录 **或** 用户手动确认 |
| 文案 | 「对已创建的监测任务运行联合分析，系统将汇总新闻并生成报告。也可配置外部定时调度。」 |

#### Step 4 — 查看分析报告

| 项 | 内容 |
|----|------|
| 目标 | 在专题分析页查看报告详情 |
| 引导方式 | 导航 `/app/reports`；若有报告则自动选中最新一条并高亮 InsightGrid |
| 完成判定 | 用户打开任意报告详情 **或** `report_count >= 1` |
| 空状态兜底 | 若无报告：「分析可能仍在生成，您可先查看示例」+ 嵌入 Landing 样例报告只读预览 |
| 完成庆祝 | Toast「恭喜完成新手引导！」+ 可选 confetti 微动画（轻量） |

### 7.4 Welcome Guide UI 形态

| 形态 | 适用 | 说明 |

| **Step Spotlight** | 各步骤 | 半透明遮罩 + 箭头指向目标控件 |

## 13. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| Gateway 未配置 | Step 1/3 无法真正跑通 | Guide 中明确前提；提供「仅体验 UI」与文档链 |
| 联合分析异步耗时长 | Step 4 长时间空状态 | 轮询 + 「分析生成中」状态；提供示例报告兜底 |
| 路由迁移破坏书签 | 老用户 `/` 404 | 301 重定向、`/chat` alias |
| 示例数据合规 | 虚构内容误认真实行情 | 统一「虚构示例」角标；禁用真实公司/商品名 |
| demo 账号滥用 | 共享账号被刷接口 | 写操作 403、对话低配额、每日数据重置 |
| Android Capacitor | Landing 在 App 内是否展示 | App 内首次启动可跳过 Landing 直接登录（Deep link 配置） |

| # | 问题 | 决策 |
|---|------|------|

## 16. 总结

本方案通过 **Landing Page（见价值）→ Quick Start（知路径）→ Welcome Guide（做闭环）** 三层结构，解决当前「登录前不知产品、登录后不知操作」的核心体验断层。示例内容**完全虚构**；访客可通过 **demo 试用账号** 零注册体验完整界面；新注册用户默认进入 **聊天 `/app`**，Welcome Guide 以 **3 步主流程** 引导（API Key 步骤默认折叠为可选）。

**下一步**：按 §12 实施分期进入开发；Phase 1 优先 Landing + 虚构静态样例 + demo 账号。
